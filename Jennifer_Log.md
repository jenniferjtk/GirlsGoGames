Hours Worked: 10 
I started by migrating the Supabase backend since the original team's project had gone inactive and the app couldn't connect to anything. Then I created a new Supabase project and recreated all six tables by reading through the codebase since there were no migration files or documentation left behind.
I set up Azure Speech Services under my Azure for Students account to connect the speech pattern recognition capabilities
I fixed the credential security issue from our Milestone 1 evaluation. The Supabase URL and anon key were hardcoded in config/config.dart and flutter_dotenv was misconfigured as a dev dependency. I rewrote config.dart to read credentials from dotenv.env at runtime instead. I accidentally removed the color constants in the process which broke several screens, so I had to add those back manually.
I found a bug in which the app was still failing even after the credential fix because there was a leading space in the .env file before the URL value (SUPABASE_URL= https://...) which was being included in the string. Removing the space fixed the URL issue, then I had to find the updated anon key from Supabase since it had been incorrect when I first pasted it.
I fixed the teacher dashboard Add New Student feature which was calling a Supabase Edge Function that no longer existed in our project. I replaced it with a direct database insert. I had to handle the session carefully since supabase.auth.signUp() client-side automatically logs you in as the new user, which would have kicked the teacher out. I made sure the teacher session was restored after the student was created.
I ran flutter analyze and cleaned up the inherited warnings from 49 issues down to 37 info-level only, removing unused imports and unused fields without touching any business logic.

I rebuilt feedback.dart, which was a fully hardcoded placeholder (always "cat," always 88%, fake phoneme chips), so it shows the real word and real AssessmentResult from the student's last attempt. Phoneme-level data doesn't actually exist in our AssessmentResult model, only word-level accuracy, so I replaced the fake phoneme chips with a real accuracy/fluency/completeness breakdown instead of faking that too.

I spent a large chunk of time chasing a microphone permission bug that made the Practice screen say "you need to enable permissions" on both simulator and a real iPhone, even after granting access. I ruled out a long list of suspects (TCC cache, MDM restrictions, Screen Time, audio input routing, xcode-select misconfiguration, a full simulator erase) before finding the actual cause: the permission_handler iOS plugin silently hardcodes every permission check to "denied" unless you add a PERMISSION_MICROPHONE=1 macro to the Podfile, which was missing. There was also a second, separate bug where the code never called setState() after the permission result came back, so the screen never refreshed even once permission was actually granted. Fixed both, plus added a web-specific bypass since Chrome handles mic permission through its own dialog.

I removed the media_kit package, which was crashing the app on iOS ("Cannot find Mpv.framework"). It turned out not to be dead weight — the teacher's student-attempts screen used it to play back a student's recording — so I replaced that one usage with just_audio instead of just deleting the feature.

I found the pronunciation feature was failing with "Network Error" and traced it to an invalid/stale Azure key (confirmed with a direct curl test that returned 401 Unauthorized) rather than a real network problem. After getting a valid key, I also noticed the key was being called directly from the Flutter app and bundled into the compiled app via .env, which violates our own rubric requirement that all API calls route through the backend with no key embedded client-side. Added a /assess-pronunciation route to our existing Node backend and moved the key there instead.

I implemented the two things our PRD commits to for the pronunciation pillar that weren't done yet: recordings now auto-stop at 3 seconds (there was a countdown in the code but it was commented out and never wired up), and I extracted all the Azure networking/retry/parsing logic out of the practice screen into a dedicated services/pronunciation_assessor.dart behind a swappable PronunciationAssessor interface, matching what the PRD describes.

Also tuned the TTS speech rate down (0.7 to 0.45) since it was reading words much too fast on iOS, and split all of the above into separate, logically-grouped commits rather than one giant commit, including reconciling a merge conflict with a teammate who had independently patched the same media_kit crash.
